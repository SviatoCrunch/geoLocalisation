# Fine-реранк (MAGSAC++): GPU-порт vs cv2 + результати на Kramatorsk

**Коротко для команди**

1. **GPU-порт MAGSAC++ повністю відповідає cv2** на реальних даних (800 000 викликів): однакові скори, однакові криві top-K, стабільно між запусками. Можна ставити замість cv2.
2. **GPU швидший** на verify (~1.8–3×); операційно повний прогін — cv2 **години**, GPU-реплей **хвилини** (виграш на батчінгу/масштабі).
3. **Якість локалізації на Kramatorsk низька (top-5 @250м = 0.15)** — через **косу FPV-зйомку**, а не метод. Для порівняння: на **Kupyansk top-5 ≈ 0.80** (панорамна зйомка ≈ надир). Реранкер — **zero-shot, без навчання**, і все одно витягує правильну зону.

---

## 1. Що тестували

Двостадійна геолокалізація: coarse (shortlist top-100 клітинок) → **fine-реранк**. Fine — **training-free**: DINO mutual-NN між кадром і клітинкою мапи → `cv2.USAC_MAGSAC` гомографія → score = inliers / #query-патчів. Агрегація `level_agg=sum`, `cell_agg=mean` (рецепт, що працював на Kupyansk).

Ми зробили повний **діагностичний архів** цього cv2-кроку на **40 test-кадрах Kramatorsk** (800k викликів, H/mask/відповідності/scores кожного), і порівняли з GPU Torch-портом MAGSAC++ на **тих самих** входах.

## 2. Загальні метрики (cv2), 40 кадрів

| | top-1 | top-5 |
|---|---|---|
| distR@250м | 0.125 | **0.15** |
| distR@500м | 0.125 | 0.30 |
| distR@1000м | 0.20 | 0.375 |
| медіана похибки | 6311 м | 1440 м |

coarse recall@100: **@1000м = 1.0** (правильний ~1-км тайл завжди в шортлисті), @250м = 0.175. cv2-викликів 800 000, **невдалих 0**.

## 3. GPU ≡ cv2 — паритет

**Per-call (800 000 викликів):**

| метрика | значення |
|---|---|
| середнє Δinliers (gpu−cv2) | **−0.039** (≈0) |
| медіана Δinliers | **0** |
| середнє \|Δ\| | 1.57 |
| точних збігів | **20.3 %** |
| зсув по рівнях піраміди | −0.01…−0.06 (без систематики) |

**Ранжування (top-5):** cv2 @250м **0.15** == GPU **0.15**; @500м 0.30 / 0.325; @1000м 0.375 / 0.425; розбіжності 1–2 кадри в обидва боки (симетричний шум MAGSAC).

**Стабільність між запусками** (`--repeats`, 10 кадрів): `gpu_lost 0 ± 0`, `top5@250м 0.100 ± 0.000`, Δinliers −0.021 ± 0.004. cv2 лежить усередині власного seed-розкиду GPU → ознака «той самий естиматор».

**Контроль:** груба `gpu_batch` MSAC-апроксимація **НЕ** збігається (середнє Δ −7, кореляція 0.14) — відповідає cv2 саме вірний **MAGSAC++ порт**.

## 6. Чому Kramatorsk 0.15, а Kupyansk 0.80

| місто | fine top-5 @250м | зйомка |
|---|---|---|
| **Kupyansk** | **≈ 0.80** | панорамна / оглядова ≈ надир |
| Kramatorsk | 0.15 | коса близька аналогова FPV |

Той самий пайплайн, рецепт і (cv2≡GPU) верифікатор. Різниця — **ракурс зйомки vs надирна мапа**:
- панорама Kupyansk → ракурс близький до мапи → справжні DINO-відповідності → inliers концентруються на правильній клітинці → **гострий пік score** → 0.80;
- коса FPV Kramatorsk → великий розрив ракурсу → mutual-NN переважно випадкові → inliers ~5 % **скрізь однаково** → правильна клітинка не формує піку (медіанний ранг 16/100) → 0.15.

**Естиматор тут ні до чого** (cv2 і GPU однакові). Важіль точності на FPV — **крос-view matching / ректифікація ракурсу**, не солвер. При цьому навіть на FPV реранкер (zero-shot) витягує зону: @1000м 0.775 на top-20, recall правильної клітинки 0.10→0.58→1.0.

## 7. Швидкість

- **verify:** cv2 ≈ 0.88 мс/виклик (1 CPU-ядро) vs GPU ≈ 0.3 мс амортизовано → **~2–3×**; виділений бенч ~1.8× (T4). Виграш GPU — у **батч-throughput** (~3300 vs ~1100 пар/с).
- **операційно:** повний cv2-прогін ~2 год 19 хв (увесь пайплайн + запис архіву 800k); GPU-реплеї ~17 хв. На масштабі GPU — **години → хвилини**.

## 8. Висновки / рекомендації

1. **GPU-порт MAGSAC++ = cv2** за якістю (per-call, криві top-K, стабільність) і **швидший** → можна використовувати замість cv2.
2. **Низька точність на Kram — це дані (косий FPV), не метод/естиматор.** На панорамній зйомці (Kupyansk) той самий zero-shot реранк дає 0.80 top-5.
3. Для покращення <250м на FPV — працювати над **matching/ракурсом** (крос-view), а не над солвером; fine можна використовувати як **звужувач top-15/20** під сильніший фінальний крок.
